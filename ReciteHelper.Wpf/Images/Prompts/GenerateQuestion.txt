Please generate review questions based on the text content.

Generate a balanced mixture of choice, fill-in-the-blank, and written questions. Each question has one type. Choose written types from TermDefinition, ShortAnswer, Essay, Discussion, and Comprehensive according to the task.
Never generate TrueFalse questions. TrueFalse questions are reserved for imported examination papers.

General rules:
- Every text field must be a real question or task prompt. Never copy a declarative knowledge sentence directly as a question.
- Knowledge points that are only statements belong in know, not bank.
- Fill every answer field with a reliable answer based only on the source material.
- Include source_excerpts for every question. Quote the passage that supports the answer verbatim from the current source block. Use enough surrounding words to locate it uniquely and list the evidence in the order it appears.
- Return chapters and questions in the order in which their evidence first appears in the source. The app uses the excerpts to restore that order after parallel generation.
- Keep review_tag as an empty array.
- Generate enough questions for the current block. For a normal block, produce about 6-12 useful questions when the source material supports it.
- Question quantity and chapter quantity are different: do not reduce the number of questions just because there are only a few broad chapters.

SingleChoice:
- Use type = "SingleChoice".
- Generate exactly four structured options with ids A, B, C, and D.
- Do not embed options inside text.
- correct_option_ids must contain exactly one id; correct_answer must contain the same id.
- correct_answers must be an empty array.

FillBlank:
- Use type = "FillBlank".
- Replace each answer position in the stem with ________.
- Put answers in correct_answers in the same order as the blanks.
- For one blank, also put that answer in correct_answer for compatibility.
- Keep options and correct_option_ids empty.
- Prefer one clear knowledge point per question. Use multiple blanks only when they form one inseparable fact.

TermDefinition:
- Use type = "TermDefinition".
- Format text as "名词解释：术语".
- Put the complete definition in correct_answer.
- Keep correct_answers, options, and correct_option_ids empty.

Other written questions:
- Use type = "ShortAnswer" for 简答题, "Essay" for 解答题, "Discussion" for 论述题, and "Comprehensive" for 综合题.
- Start the stem with a clear task word such as 简述、说明、分析、比较、阐述、为什么、如何、哪些.
- Put a concise course-level reference answer in correct_answer. For open-ended tasks, give one sufficient example.
- Keep correct_answers, options, and correct_option_ids empty.

Grading nature for written questions:
- Set answer_nature to "Conceptual" for essential facts and concepts, "Expressive" for analysis, applications and open-ended responses, or "Conceptual, Expressive" for a question that asks for both.
- For a question with multiple natural parts, include answer_parts. Give each part a key, prompt, reference_answer, weight, and its own answer_nature. The weights sum to 1.
- Each part represents an independently answerable task. Keep supporting details inside that part's reference answer.

Divide the content into broad chapters. Return only valid JSON for List<Chapter>, without Markdown fences.

Chapter naming rules:
- Use a small number of broad teaching units. Do not create one chapter per question, paragraph, sentence, or isolated concept.
- For a normal source chunk, 1-3 chapters are usually enough.
- If the source text contains explicit headings, section names, categories, catalogue titles, or labels, use those original names as chapter names.
- If a text block starts with "当前资料章节：", use that value as the preferred chapter name unless the following content clearly belongs to a more specific subheading.
- Do not use vague names such as "杂项题目", "其它内容", "综合", "Chapter 1", or "第1章" when the source contains a meaningful title.
- If no explicit heading exists, infer a concise teaching-unit name from the content topic.
